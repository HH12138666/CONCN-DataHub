# 部署状态

## 在当前电脑上供局域网访问

后端通过 `backend/.env` 中的 `CONCN_HOST=0.0.0.0`、`CONCN_PORT=8100` 启动，直接提供构建后的 `frontend/dist` 和 API。裁切任务由独立 worker 处理。

- 同一 Wi-Fi 的设备访问：http://172.17.119.129:8100/data/view
- 同一有线局域网的设备访问：http://192.168.1.38:8100/data/view
- 在项目根目录执行 `powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1` 启动服务。
- 首次需要在**管理员 PowerShell** 中执行 `powershell -ExecutionPolicy Bypass -File .\scripts\enable-lan-firewall.ps1`。该脚本仅放行这两个网卡、本地子网的 TCP 8100。

更换 Wi-Fi 后，当前无线地址为 `172.17.119.129/18`，对应子网 `172.17.64.0/18`。配置和防火墙脚本已更新，网站在本机通过新地址验证正常；仍需再次执行上述管理员防火墙脚本，使旧规则切换到新网络，然后用另一台设备验证实际连接。电脑需保持开机、唤醒和服务运行。若仍无法访问，检查两台设备是否在同一网络以及路由器是否开启客户端隔离。网络地址变化时需更新脚本中的 IP、子网和 `CONCN_PUBLIC_URL`。

网页代码修改后执行 `npm --prefix frontend run build` 更新共享页面。5173 是本机开发入口，分享给其他人请使用 8100。当前未配置开机自动启动。

## 后续公网部署

本目录用于后续保存公网服务器部署配置。本次只整理代码，没有生成或执行生产部署方案。

当前可运行的组成部分为：Vue 网页、Flask/Waitress 网站服务、独立 Python 裁切进程与 MySQL。网站进程可以提供 `frontend/dist`；真实裁切还需要源数据、科学依赖及 ParFlow 工具。

后续部署需要根据实际服务器、域名、证书、邮件服务、数据路径和存储规模编写代理与服务配置。当前仅配置局域网访问，尚未完成公网部署。

实际部署前还需完成真实数据验证、备份恢复、文件清理与权限验收。具体未完成事项见 [整理记录](../docs/需求规格说明书.md)。
