# ParFlow 数据共享平台部署说明 v1.0

日期：2026-09-09。本文区分“已验证的 Windows 局域网运行”和“待服务器到位后实施的公网方案”。公网部分为可供运维审核的配置模板，尚未在真实服务器执行，不可据此宣称已上线。

## 1. 当前运行形态

浏览器通过 TCP 8100 访问 Waitress；Waitress 同时提供 frontend/dist 和 /api。独立 Python worker 从 MySQL 领取任务，读取私有科学数据并生成 ZIP。MySQL 存业务数据，源文件和结果在磁盘。Vite 5173 仅供本机开发。

|组件|当前状态|
|---|---|
|Windows + Python 虚拟环境|已配置，当前本机使用 Python 3.14|
|MySQL 8.4 / MySQL84 服务|已安装，22 表业务库与独立测试库|
|前端构建|已完成|
|Waitress + worker|已启动并用于局域网试运行|
|域转换器|Windows 可执行文件已构建并配置|
|原始数据与七级目录|已接入，70,865 条目录，一份本地验证版本|
|公网服务器、域名、HTTPS|未部署|
|SMTP|未配置|
|开机自启/进程托管/集中监控|未完成生产配置|
|生产容量和恢复演练|待实施|

## 3. 当前电脑启动与访问

在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

脚本启动网站、下载 worker 和本机 Vite，日志写入 .local/runtime；检测已有端口和进程以避免常规重复启动。脚本不是生产 Windows 服务，电脑重启后需要再次启动。

当前地址（会随网络变化）：

- Wi-Fi：http://172.17.119.129:8100/data/view
- 有线局域网：http://192.168.1.38:8100/data/view
- 本机直接访问：http://127.0.0.1:8100/data/view
- 本机前端开发：http://127.0.0.1:5173/data/view

以上是私有局域网地址，不能让任意互联网用户直接访问。另一台设备需在对应可互通网络；路由器访客隔离、校园网客户端隔离可能阻止互访。电脑必须保持开机和唤醒。

### 3.1 更换 Wi-Fi

1. 查看当前 IPv4：
```powershell
Get-NetIPAddress -AddressFamily IPv4 | Select-Object InterfaceAlias,IPAddress,PrefixLength
```
2. backend/.env 中 CONCN_PUBLIC_URL 改为新 IP 的 8100 地址。CONCN_HOST=0.0.0.0，CONCN_PORT=8100。
3. 修改 scripts/enable-lan-firewall.ps1 的 LocalAddress、RemoteAddress 为新地址和实际子网。不要固定假定所有网络都是 /24；当前 Wi-Fi 是 /18。
4. 用管理员 PowerShell 执行：
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\enable-lan-firewall.ps1
```
5. 重启网站使 PUBLIC_URL 生效，检查同机及第二台设备访问。worker 若数据/任务配置未变无需为单纯公网 URL 变化重启。
6. 原 IP 的登录 Cookie 不会自动转移到新 IP，用户需要在新地址重新登录。

脚本只放行指定网卡/子网的 TCP 8100，不关闭防火墙，不对外开放 MySQL 3306。该脚本目前是针对当前两个网卡的明确配置，不是任意网络自动探测工具。

### 3.2 查看运行与停止

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8100,5173
Get-Content .local/runtime/processes.json
Get-Content .local/runtime/backend.stderr.log -Tail 50
Get-Content .local/runtime/worker.stderr.log -Tail 50
```

停止时先记录正在处理的任务，能等待的任务先完成。用 Get-CimInstance Win32_Process 核对记录 PID 的命令行确实属于本项目 app.py、datahub.workers.queue 或 Vite，再 Stop-Process 指定已核实 PID；Python 虚拟环境启动器可能有实际执行子进程，需要一起核查。不要直接停止所有 python.exe、node.exe 或所有占用端口的进程。MySQL 可保持运行。停止 worker 的当前裁切可能需要取消/核查子进程与等待租约恢复，不能把强停当成无损暂停。

### 3.3 前端更新

```powershell
npm --prefix frontend ci
npm --prefix frontend run build
```

本机已有依赖时仅改网页可直接 build。局域网 8100 使用构建产物，不会仅因修改 src 自动更新。构建后刷新浏览器，旧页面可使用强制刷新；不要删除用户业务数据来“清缓存”。

## 4. 新 Windows 开发/验证环境

本节用于**全新环境**，已有业务库不要重跑 bootstrap。

1. 安装支持项目的 Node（package.json：^22.18.0 或 >=24.12.0）、Python 和 MySQL 8.4。科学依赖须在目标系统实装验证；不要把版本范围当作跨平台保证。
2. 复制/获取源代码，在根目录创建 .venv，安装依赖：
```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements/web.txt
$env:PYYAML_FORCE_LIBYAML = '0'
.\.venv\Scripts\python.exe -m pip install -r backend/requirements/worker.txt
npm --prefix frontend ci
npm --prefix frontend run build
```
PyYAML 环境变量用于本机 Python 3.14 下相关旧依赖的纯 Python 构建；安装后执行 pip check，生产环境应保存最终实测依赖清单。

3. 全新本地数据库初始化：backend/.env 不存在，concn_datahub / concn_datahub_test / concn_app 均未创建时，从 backend 运行：
```powershell
..\.venv\Scripts\python.exe -m datahub.cli bootstrap
```
交互输入本地 MySQL 管理密码。命令创建两个库、应用账号、22 表、默认规则及本地管理员；秘密写入忽略文件。不要先复制 .env.example 再运行 bootstrap，因为命令明确拒绝覆盖已有 .env。

4. 若采用 DBA 手工建库路线，则在新空库中按 001_schema.sql、002_regions.sql、001_defaults.sql 初始化，用独立迁移账号执行，运行账号只授 SELECT/INSERT/UPDATE/DELETE；手工写 .env，创建管理员并录入必要内容。不可同时混用两条初始化路线。
5. 放入源数据，配置路径，安装/构建 pfmask-to-pfsol，确认全部 7 个级别及五种 PFB 可读。
6. scripts/build_pfmask_windows.py 是本机固定官方源码构建流程，先审查脚本依赖和输出路径。已有转换器可复用经过校验的可执行文件；不要随意替换已冻结版本的二进制。
7. 从 backend 执行 python -m datahub.cli publish-local 进行本地验证发布。它会读取大文件、校验所有边界并写入真实目录，不是只读检查；仅允许 development + 本地 MySQL，已有不同摘要同版本拒绝覆盖。
8. 根目录运行 .venv\Scripts\python.exe scripts/import_regions.py 导入省市导航；外部数据缓存位于 .local/regions，更新须核实来源和差异。
9. 启动并执行第 9 节验收。

修改 .env 后，受影响的长运行进程需重启。系统已设置的环境变量可能优先于 dotenv 文件；排错时确认实际进程配置，不公开输出密码。

|MYSQL_HOST / PORT|数据库地址|本机 127.0.0.1:3306；生产私网|

|MYSQL_USER / PASSWORD|应用连接|专用账号；不使用 root 运行|
|CONCN_ENV|运行模式|development / production|

|CONCN_COOKIE_SECURE|Secure Cookie|LAN HTTP 为 0；生产必须 1|
|CONCN_REQUIRE_VERIFIED_EMAIL|下载前验证邮箱|当前 0；真实邮件验收通过后可设 1|
|CONCN_JOB_ROOT|私有任务根目录|建议绝对路径，需空间和写权限|

## 7. Linux 公网单机方案模板

### 7.1 目录与配置假设

以下模板假定 /srv/concn/app 为经审核代码、/srv/concn/venv 为虚拟环境、/srv/concn/data 为源文件、/srv/concn/jobs 为工作目录，运行用户 concn 已创建且仅有必要权限。example.org 和证书路径是占位符，必须替换。模板没有实际安装或开启任何公网服务。

生产 .env 示例（密码通过保密渠道配置）：

```dotenv
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=concn_datahub
MYSQL_USER=concn_app
MYSQL_PASSWORD=<独立应用账号密码>
CONCN_ENV=production
CONCN_HOST=127.0.0.1
CONCN_PORT=8100
CONCN_PUBLIC_URL=https://example.org
CONCN_COOKIE_SECURE=1
CONCN_REQUIRE_VERIFIED_EMAIL=0
CONCN_JOB_ROOT=/srv/concn/jobs
CONCN_SHP_DIR=/srv/concn/data/PFBAS/shp
CONCN_TIF_DIR=/srv/concn/data/PFBAS/geotiff
CONCN_INPUT_PFB_DIR=/srv/concn/data/inputs
PARFLOW_PFMASK_CMD=/srv/concn/tools/pfmask-to-pfsol
```

验证邮件服务后决定是否把验证邮箱开关设为 1。production 代码强制检查 HTTPS PUBLIC_URL 和 Secure Cookie，两项不正确会拒绝启动。

### 7.2 数据库与科学版本迁移

选择“新空库发布正式目录”或“经批准恢复业务数据”路线；都不能运行 bootstrap 覆盖已有库。恢复完整 SQL 后不再重新执行 001/种子。仅备份 SQL 不能复制运行环境、源文件和输出。

**跨 Windows/Linux 转换器二进制必然不同，当前发布清单包含转换器和裁切代码哈希。** 不能直接复制 Windows 的发布记录、换成 Linux 转换器就认为可正常裁切。需要用目标平台依赖重新验证科学输出，形成新的发布版本/清单并经数据负责人审核。现有 publish-local 只服务本地验证，通用生产发布 CLI/后台尚未完成，这是首次公网发布的实施任务。不能通过删除 hash 检查或修改旧版本摘要绕过。

历史用户名额按编码保留；历史大流域审批绑定版本，切到新版本后是否重新审批应提前确定，不自动迁移授权范围。新旧版本数据和执行环境若需并存，当前单套源路径架构需要扩展。

### 7.3 服务托管模板

网站服务 /etc/systemd/system/concn-web.service：

```ini
[Unit]
Description=CONCN website
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=concn
Group=concn
WorkingDirectory=/srv/concn/app/backend
ExecStart=/srv/concn/venv/bin/python -X utf8 app.py
Restart=on-failure
RestartSec=5
UMask=0077
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

worker 服务 /etc/systemd/system/concn-worker.service：

```ini
[Unit]
Description=CONCN clipping worker
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=concn
Group=concn
WorkingDirectory=/srv/concn/app/backend
ExecStart=/srv/concn/venv/bin/python -X utf8 -u -m datahub.workers.queue
Restart=on-failure
RestartSec=5
KillMode=control-group
TimeoutStopSec=30
UMask=0077
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

实际数据库服务名随系统而异，若使用本地 MySQL 可添加正确的依赖；勿直接假定 mysqld.service 一定存在。先校验目录权限，再加载并启动服务。重启策略和停机语义依 systemd 实际配置，见[官方服务手册](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html)。

### 7.4 Nginx HTTPS 模板

```nginx
server {
    listen 80;
    server_name example.org;
    return 301 https://example.org$request_uri;
}
server {
    listen 443 ssl;
    server_name example.org;

    ssl_certificate /etc/letsencrypt/live/example.org/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.org/privkey.pem;
    client_max_body_size 1m;

    location / {
        proxy_pass http://127.0.0.1:8100;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_buffering off;
        proxy_read_timeout 300s;
    }
}
```

当前由后端统一处理前端路径和文件授权，模板不直接 alias 私有 ZIP。Host 保持正式域名，避免同源写入校验错误；关闭代理响应缓冲可避免大包重复写入代理临时目录，但会让慢连接占用上游更久，需压测。参数语义见 [Nginx 官方代理模块](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)。

**生产限流差距：**当前后端按 request.remote_addr 做单进程限流，经过反向代理可能全部被识别成代理 IP。模板传头并不会自动让 Flask 信任它们。正式上线前需在可信单代理范围配置真实 IP 处理并测试，或落实代理层限流并调整应用策略；不能直接信任来自公网任意客户端的转发头。本模板尚不包含完成的集中限流方案。

公网防火墙仅开放所需 HTTP/HTTPS 和受控运维入口，8100/3306 留在本机或受限私网，5173 不开放。确认代理配置测试通过、证书有效后才 reload；证书续期由所选证书工具落实并实测。

## 8. 上线和更新顺序

1. 记录当前发布编号、依赖清单、数据库版本和源文件摘要，备份。
2. 在独立验证环境安装依赖、执行 SQL 增量、构建前端，跑测试。
3. 科学源/转换器/管线变化必须形成新冻结版本；一般 UI 修复不更改科学版本。
4. 正式环境开启维护模式暂停新申请/任务；注意这不是阻断所有 GET 或所有正在传输的下载。
5. 等待在途任务完成或按业务批准取消；避免在裁切中更改同名源文件。
6. 更新代码与构建产物；有后端变化重启网站，有 worker 变化重启 worker。
7. 健康检查、登录、查询、申请列表、权限下载和日志检查通过后解除维护。
8. 保留上一版本代码/配置及数据库备份；遇到结构不兼容不能只回滚前端。
9. 通知用户刷新页面；HTTP IP 换域名会有独立 Cookie，需要重新登录。
10. 记录部署时间、操作人、影响任务、回滚点及验证证据。

## 9. 验收命令与边界

当前环境可用的只读健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8100/api/health
Invoke-RestMethod http://127.0.0.1:8100/api/config
```

本地测试（会操作独立测试数据库）：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
node --test frontend/tests/*.test.js
npm --prefix frontend run build
```

不要指向生产库运行测试；test_datahub 明确使用 concn_datahub_test，fixtures 会清空该测试库业务数据。

旧真实下载验收脚本依赖旧版本和旧ZIP格式，已移出发布源码。新的真实下载验收需按当前API和10文件规范执行，不能作为每分钟健康探测。worker --once 同样会领取并处理任务，不能用于只读检查。

## 10. 常见故障

|现象|排查与处理|
|---|---|
|本机能访问别人不能|核实 IP/子网、监听地址、防火墙规则及路由器隔离；用 8100 链接|
|HTTP IP 出现 randomUUID 报错|已修复为 getRandomValues 兼容逻辑；重新构建并刷新旧页面，不关闭浏览器安全机制|
|申请页面空白|旧版本 setup 初始化 requestKey 报错会导致空白；刷新新构建，检查登录与控制台|
|下载列表周期闪烁|已改为在途任务静默轮询；确认新构建加载|
|网页旧布局|8100 读 frontend/dist，确认 build 完成并刷新；5173 为开发入口|
|健康接口数据库错误|MySQL 服务、账号、库名、网络/连接权限；不要把密码输出到共享日志|
|一直排队|worker 未启动、同账号已有运行任务、队列/数据库连接异常|
|裁切失败|检查 worker 与任务日志、源路径、哈希、转换器、空间和超时|
|生产启动失败|HTTPS PUBLIC_URL 和 COOKIE_SECURE=1 是否设置正确|
|登录成功后写操作 403|检查 X-DataHub 头、Origin 和 PUBLIC_URL/代理 Host|
|文件 410|结果或下载授权到期、文件缺失、审批到期；重新取得有效权限后生成/下载|
|地图背景空白|外部底图网络或密钥问题，检查标准/地形服务；流域数据本身可能仍正常|
|邮件入口失败|SMTP 未配置或 STARTTLS/发件人权限不匹配；先验收实际收信|
|重启后原站打不开|本机脚本未设开机自启；重启服务，或按生产方案配置托管|
